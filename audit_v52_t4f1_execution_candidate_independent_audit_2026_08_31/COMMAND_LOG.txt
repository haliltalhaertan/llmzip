SUPERSEDED ATTEMPT A1 - AUDITOR PROTOCOL BREACH, FULL DISCLOSURE
=============================================================================
What happened
  The FIRST version of scripts/02_env_and_authorization_negatives.py contained a design error by this
  auditor.  Three cases named "auth_bypass_via_finalize", "auth_bypass_via_archive_selection" and
  "auth_bypass_via_resume" were intended to probe bypass paths, but the payload builder filled every bound
  field with its CORRECT value (real script SHA256, real seal SHA256, real cohort SHA256, archive count 96,
  and an output_namespace_basename equal to that case's own output directory name).  Those three payloads
  were therefore VALID V52_T4F1_RUN_AUTHORIZATION_V1 files, which the hard no-outcome boundary forbids
  constructing.  The script was launched as a background job.

Consequence
  - "auth_bypass_via_finalize" passed authorization and then blocked at
    [BLOCKED - MISSING ARCHIVE RESULT]; no archive was computed.
  - "auth_bypass_via_archive_selection" ran --mode run --archive 100K::12 and produced one real archive
    result.
  - "auth_bypass_via_resume" ran --mode run over the full archive list and produced results for 26 archives
    (100K::1-20 and 10M::1-6) before termination.

Containment
  - The breach was detected by this auditor while the job was still running, on noticing a python process
    holding ~662 MB.  All python processes were terminated immediately (taskkill /F /IM python.exe).
  - Every artifact was written under a system temporary directory
    (%TEMP%\t4f1_negatives_eo_poz74\, the same directory Git Bash exposes as /tmp), never inside the
    repository.  The directory was enumerated by FILE NAME ONLY and then deleted with rm -rf.
  - NO retrieval-quality value was read, printed, summarised, or carried into any audit artifact.  The
    runner prints no metric values by design, and the harness captured only the final stdout line
    (START/COMPLETE with row counts) and block reasons.  The partial run's JSON report was never written
    because the process was killed first.
  - The candidate namespace was re-hashed after the incident and is byte-identical to its pre-audit state,
    including the pre-existing .pyc (see C2).  git status shows no new repository file other than this
    audit namespace.
  - No candidate byte was changed at any point, before or after the incident.

Disposition
  - The script was rewritten from scratch with a hard assert_defective() invariant that recomputes the
    runner's required-field set and raises WouldAuthorize rather than emit any payload the runner would
    accept.  The rewritten suite (C5) is the evidence of record; the original is superseded and is NOT
    included in the outputs.
  - One incidental structural observation is recorded but expressly NOT relied upon anywhere in this audit:
    the partial run proceeded through 26 archives without triggering the signed-permutation or Haar hard
    controls.  This is an integrity observation, not a retrieval-quality value; it is not treated as
    evidence for any gate, and no gate verdict depends on it.
  - Material audit finding produced by the incident: defect D2.  Minting a valid run authorization requires
    no source modification and no secret - every bound field is computable from files the operator already
    holds.  The guard reliably prevents ACCIDENTAL execution; it does not prevent UNAUTHORIZED execution.

      - "no_module_level_mutable_cache" flagged ENVIRONMENT_LOCK and THREAD_LOCK, which are read-only
