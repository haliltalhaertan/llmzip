## (a) The 12-byte framing is HONEST — the strongest case the evidence allows

1. **The programme has a written, binding definition, and the 12-byte figure complies with it.** L-088 (`docs/CONTINUITY_LEDGER.md:1873-1900`, VERIFIED read): "twelve bytes means at most twelve MARGINAL PERSISTENT BYTES PER VECTOR. Everything written once per stored memory counts… Shared model state… sits outside the cap but is ALWAYS reported separately in bytes." SIGN96 stores 12 B per vector and (modulo preprocessing state — see honest-side weakness 5) carries no per-vector auxiliary. Under the programme's own binding rule, calling it 12-byte is compliant, not deceptive.
2. **Marginal-vs-shared is a standard, defensible accounting split.** The cost evidence measures all five arms as `S(N) = a + bN` with max abs residual 0.00 B (CLAIM in `origin/evidence/twelve-byte-cost-2026-09-11:evidence/twelve_byte_cost_2026_09_11/README.md`; the replay receipt confirms strict non-environment equality with zero differing leaves — CLAIM in `origin/codex/twelve-byte-runtime-replay-2026-09-12:evidence/runtime_replay_2026_09_12/COMPARISON.json`: `strict_non_environment_equal: true, differences: []`). Linearity with slope exactly 12 for SIGN96/PQ96/OPQ_PQ96 makes "12 marginal" a measured property of the serialization, not a slogan. A routing code's scan-time job is per-vector bytes; shared state is read once, not per candidate — so marginal cost is the operationally relevant quantity for the retrieval path.
3. **Shared state is not hidden — it is separately reported by rule.** The HR decision mandates `marginal_bytes_per_vector` + `shared_state_bytes_per_archive` always carried, effective optionally derived (VERIFIED: `origin/hr/twelve-byte-budget-decision-2026-09-11:docs/v52/V52_TWELVE_BYTE_BUDGET_HR_DECISION_2026-09-11.md`, "Reporting" section). The revision strengthens this to mandatory effective (VERIFIED: `PREREG_DRAFT.md` lines 103-111: "Effective cost is mandatory in this revision so small-archive costs stay visible"). A framing that *requires* publishing 287.69 B/vector and 88,886 B/vector alongside 12 B is disclosure, not concealment.
4. **The programme caught and cancelled its own overreach.** The original prereg's primary contrast SIGN96−RABITQ96 compared 12 B against 20 B; L-088 cancels it as written and demotes RaBitQ96 to ineligible (VERIFIED ledger text). The revision's arm table labels RABITQ96/EXT_RABITQ96 INELIGIBLE and quotes index-only effective costs with the warning "Additional preprocessing would increase these index-only costs" (VERIFIED: `PREREG_DRAFT.md` lines 125-152). Self-correction on the record is evidence of an honest accounting culture.
5. **The 88,886 figure is not the SIGN96 deployment figure — conflating them is the critic's error, not the programme's.** The projector pilot measures the *lexical+SVD fitting projector* (TF-IDF vocabs, sv, s96, mu), which is common preprocessing, not the SIGN96 code itself. ## (b) The 12-byte framing MISLEADS — the strongest case the evidence allows

1. **At deployed scale the shared state dominates by 3–4 orders of magnitude, and no measured format fixes it.** VERIFIED numbers: projector effective 80,267–104,464 B/vector across the 15 archives (float32); cheapest measured format (f16+zlib) still 30,769–39,718. OPQ index-only effective mean 287.69 B/vector (VERIFIED recomputation to all 16 digits). A reader hearing "12 bytes vs 384 bytes" infers a ~32× saving; the measured total-footprint ratio for the actual pipeline is ~0.004× (88,886 vs 384 goes the *wrong way* — the "compressed" system stores ~230× MORE per vector than raw float once shared state is counted). The 32× inference is not approximately true; it is sign-inverted.
2. **Break-even requires millions of vectors; archives hold hundreds — a factor of ~7,400.** VERIFIED: break-even N(→12) = 3,685,020 (float32) down to 1,411,767 (f16+zlib); measured N = 443–551; frozen range 396–616. Even matching *float parity* (effective ≤ 384) needs N ≥ 118,872 per projector — 193× the largest archive. This is not a "grows out of it at scale" situation within any archive-local design.
3. **The obvious rescue — share one projector globally — fails arithmetically AND is preregistered away.** VERIFIED: all 470 archives hold 231,606 vectors total; one shared 44.2 MB projector still costs 202.93 B/vector effective (109.95/114.47/85.15 for the cheaper formats) — 7–17× the marginal cap. And the revision forbids the rescue by rule: "Never amortize state over all benchmark questions. A global codebook is a different, untested deployment" (VERIFIED: `PREREG_DRAFT.md` lines 79-81). So the honest-side "shared amortizes" argument is both quantitatively insufficient and procedurally out of bounds.
4. **The founding question was asked in unqualified language.** The pushed prereg asks: "At a fixed 96-bit (12-byte) budget, is SIGN96 competitive…?" with an arms table headed "budget" listing "96 bit" (VERIFIED: `origin/draft/v52-twelve-byte-baseline-prereg-2026-09-10:docs/v52/V52_TWELVE_BYTE_BASELINE_PREREG_2026-09-09.md`, §1 and §4 arms table). ## Where both stories are weak (adversary's fee)

- The HONEST side leans on "shared state is reported separately" — but for the faiss arms the full shared state (index S0 + preprocessing) has never been measured together in one package; the rule exists, the complete number does not (VERIFIED: revision §4 gate "not implemented or satisfied here").
- The HONEST side's "operationally relevant = marginal" claim assumes the retrieval path never re-reads shared state per query at a cost that matters (latency/RAM), which no document measures — the projector report explicitly lists query-latency effects of compression as "bakılmadı" (CLAIM).
- The MISLEADS side's sign-inversion point (88 kB > 384 B) compares the research pipeline's *fitting* projector against float payload as if both must ship per vector — but the float baseline presumably needs the same lexical machinery to build queries, a symmetry no document quantifies. If FLOAT96 also needs a projector to encode queries, part of the 88 kB is common-mode, not SIGN96-specific overhead. **Neither side has the common-mode analysis.**
- Both sides assume archive-local fitting is the deployment; a production system would almost certainly fit once globally. The revision declares that deployment "different, untested" — which protects the experiment's validity while leaving the *practical* question ("what would 12-byte retrieval really cost?") entirely unanswered. The honest accounting of an experiment can still mislead about the product.
