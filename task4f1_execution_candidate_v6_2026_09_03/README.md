# V52 Task 4F1 — Execution Implementation Candidate V4

This namespace contains a guarded, outcome-capable implementation candidate for the sealed 1,712-question BEAM restricted cohort.

It is prepared for independent code audit only. It is not a Task 4F1 preregistration, run authorization, or permission to inspect retrieval-quality outcomes.

The implementation has three modes:

- `preflight`: verifies exact byte/environment/corpus/cohort bindings and runs synthetic invariance tests without computing BEAM retrieval quality;
- `run`: processes authorized archives with atomic, provenance-bound per-archive checkpoints but refuses to start without a Head Researcher HMAC authorization bound to the final audited script, seal, cohort, preregistration and output namespace;
- `finalize`: refuses partial finalization and requires all 96 eligible archives before producing aggregate files.

Payload closure is recursive; generated bytecode and nested unbound files are forbidden. Every checkpoint binds the script, cohort, execution seal and run authorization hashes.

Finalization additionally refuses every pre-existing derived output or temporary path, recomputes all three metrics from the frozen gold IDs and retrieved IDs, and requires exact Native-versus-signed-control top-three IDs and distances at every seed/trial cell.

The candidate seal must remain `PREPARED_NOT_INDEPENDENTLY_AUDITED`. Its authorization-key commitment remains `PENDING_HEAD_RESEARCHER_PREREGISTRATION`, so `run` and `finalize` are cryptographically fail-closed. No authorization secret or `RUN_AUTHORIZATION.json` exists in this namespace.

Current authorization:

- `TASK 4F1 RUN = BLOCKED`
- `RETRIEVAL-QUALITY OUTCOME ACCESS = FORBIDDEN`

## V4 change versus V3 (Gate 3 remediation)

The V3 cold-start independent audit returned `BLOCKED` on Gate 3. Its finding: the
pinned `100K::12` canary bound bit-exact float digests, which depend on BLAS/LAPACK
kernel dispatch. Holding code, data and every locked package version constant and
varying only `OPENBLAS_CORETYPE` produced four distinct archive digests across six
dispatches, none matching the sealed value, while `verify_environment()` accepted all
of them. A load-bearing gate was therefore machine-bound rather than lock-bound.

V4 changes only the canary and environment provenance:

- The canary now binds **sign-code digests** (`np.packbits(centered >= 0)`), which are
  the quantities that actually drive Hamming retrieval. These were byte-identical
  across all six kernel dispatches.
- It adds a **sign-stability margin**: the smallest `|value|` must exceed
  `CANARY_SIGN_MARGIN = 1e-9`. Measured cross-dispatch numerical spread is ~1.2e-13
  while the nearest entry to a sign flip is ~4.09e-07, a margin of roughly 3.4e6.
- `verify_environment()` additionally **records** the BLAS/LAPACK build and coretype
  as provenance. It does not gate on them, because sign codes no longer depend on them.
- The canary still performs no ranking, opens no probing questions and loads no gold.

Everything else is carried over from V3 unchanged, including the audited B1, B2 and B3
repairs and the entire numerical core (representation fitting, query transformation,
ranking, signed/Haar/ITQ algorithms, seeds, thresholds, tie priority, trial generation,
metric definitions and aggregation formulas).

Status: `PREPARED_NOT_INDEPENDENTLY_AUDITED`. V4 was prepared by the implementer role
and has NOT been independently audited. Task 4F1 remains blocked for preregistration
and execution.

## V5 change versus V4 (co-chair finding CC-01)

The V4 independent audit passed all nine implementation gates, but the co-chair review
found CC-01: the bound `EXECUTION_SPEC.md` carried two mutually exclusive normative canary
definitions — the superseded V3 raw-float digests alongside the V4 sign-code digests. Only
the latter is implemented and audited, and the V3 requirement is unsatisfiable on conformant
hardware. V4's package seal was withdrawn.

V5 is a purely declarative remediation:

- one normative canary definition in `EXECUTION_SPEC.md`; the superseded raw-float
  requirement is deleted and both V3 digests are enumerated as deprecated literals
- `NORMATIVE_SOURCE_MAP.json`: one authoritative source per load-bearing concept, with every
  repetition typed as a derived mirror
- `candidate_package_preflight.py` gains a single-source gate that proves one source per
  concept, equal typed mirrors, zero surviving deprecated literals across the whole bound
  closure, and runner byte-identity with the accepted V4 runner
- the seal now records `status_at_audit_submission` only; post-audit acceptance lives solely
  in a detached hash-bound attestation
- the stale V3 preflight docstring and authorization-template label are corrected

The retrieval runner is **byte-identical** to the accepted V4 runner
`f96cba2c1f10a5f873e9f6cfa395dbce5432aa9d3940791ab8aa2d2f273621f8`. No representation,
method, seed, threshold, priority, metric, aggregation, checkpoint, finalization or
authorization behaviour changes.

V5 is a **package** version, not a schema version: because the runner is byte-identical,
every schema literal it verifies stays at its V4 value. Relabelling them would break the
byte-identity constraint or make the payload fail closed against its own runner.

Status: `PREPARED_NOT_INDEPENDENTLY_AUDITED`. Task 4F1 remains blocked for preregistration
and execution.

## V6 change versus V5 (BLOCKED V5 delta audit)

The V5 delta audit confirmed CC-01 was repaired and the change set was declarative, but blocked
because the single-source mechanism did not establish its own claim: the gate trusted a
hand-written mirror list, so it verified only what its author declared, and it compared raw text
line by line, so the same digest wrapped across two lines or written in uppercase slipped past it.

V6 inverts the burden. The gate sweeps every bound payload for value-shaped tokens (sha256, git
sha1, `V52_*` identifiers) and holds each discovered token to account: it must be attributed to a
declared concept, and it must appear only at that concept's authoritative path or a declared
mirror. An unattributed token fails as a missing concept; an attributed token in an undeclared
place fails as an unlabelled second normative source. All matching runs on normalised text with
whitespace stripped and case folded.

Also corrected: five runner-enforced anchors and tie priority now have concepts (24 total, up
from 18); `PAYLOAD_HASHES.json` no longer carries a second status field; and the attestation is a
real resolvable file that actually holds the V6 record.

The retrieval runner remains byte-identical to the accepted V4 runner
`f96cba2c1f10a5f873e9f6cfa395dbce5432aa9d3940791ab8aa2d2f273621f8`.
