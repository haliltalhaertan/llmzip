# A1 — bind LongMemEval diagnostics to the actual sorted global ordinal

Prior candidate: `24d3351f068f6982148c14a9e3338c29a2769449`.
Independent audit: `2a025ee3b85f25af80e1b939f85f23c6cf06af30`, NOT ACCEPTED.
This fix is within the existing G-3 synthetic fix-and-test grant.

The pipeline already prepares LongMemEval archives in sorted question-ID order.
The bridge had instead attached question IDs by input cohort order, then checked
that same incorrect convention. For input `[q_z,q_a]`, ordinal0's actual q_a
diagnostics could be labeled q_z. The fix uses the sorted global ID ordinal for
binding and validation. Input cohort order and records are preserved; no ordinal,
seed, retrieval algorithm or certificate in the preparation pipeline is changed.

The new test generates exact two-question synthetic LongMemEval-shaped bytes.
Only the source/mapping admission checks are replaced by equality checks of those
generated bytes, as in the original suite; parser, representation, controls,
scoring and envelope builder run unchanged. A forwarding observer records the
actual question at each pipeline ordinal, independently of the bridge's lookup.
Both sorted and unsorted cohorts must map to that observed identity. A swapped
diagnostic-ID payload with a recomputed binding hash must still be rejected.
